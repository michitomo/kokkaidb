# 09. 信頼性・透明性・出典

[← 戻る](README.md)

本サイトは政治発言を扱うため、技術的精度より**ユーザーが信頼できる情報源だと感じられるか**が長期成功を左右する。法的リスクの予防にもなる。

---

## 9.1【P0】「サイトについて／方法論」ページが無い

[05 章](05-qa-quality-metrics.md) でも触れたが、本格稼働前に最低限必要なページ:

| ページ | URL | 必須項目 |
|------|-----|--------|
| About | `/about` | 運営主体 / 連絡先 / 趣旨 / 利用規約 |
| 方法論 | `/about/methodology` | パイプライン / モデル / 既知の限界 / 評価指標の定義 |
| データ仕様 | `/about/data` | JSON スキーマ / ライセンス / 更新頻度 |
| 利用規約 | `/about/terms` | 商用利用可否 / 引用ルール / 免責 |
| 訂正・問合せ | `/about/contact` | 誤字・誤判定の報告フォーム or メール |

これらが無いまま稼働すると、メディアからの問合せに毎回個別対応する必要がある。

---

## 9.2【P0】「LLM 自動評価」であることの注意書き

### 現状
- 出所リンクは丁寧（フッタ＋セッション詳細＋Q&A カード）
- しかし「**この要約／回避度／コミットメント抽出は LLM 自動生成**」の注記が**1 文字もない**
- 法律的にも、LLM 出力を「事実」と読まれた場合、運営に責任が来る

### 改善案
1. **全ページのフッタに常時注記**:
   ```
   ⚠️ 要約・分類・評価は LLM（DeepSeek V3.2）による自動生成です。
      公式議事録・動画原本を必ず併せてご確認ください。
   ```
2. Q&A カード上部に小さく `[LLM 要約]` バッジ
3. 検索結果カードに同バッジ
4. methodology ページへのリンクを各バッジから

---

## 9.3【P1】出典リンクの粒度

### 現状（良い点）
- セッション詳細上部: 出所 → 衆議院TV
- Q&A カード下部: 出所 → 衆議院TV
- フッタ: 衆議院TV / 参議院TV

### 改善余地
- セッション詳細の出所が小さく薄いグレー → 信頼担保のためにはもう少し目立たせて良い
- Q&A 動画リンクの「該当秒へジャンプ」が中心だが、「動画全体（先頭）」のリンクも添える
- 公式議事録（衆議院議事速報など）が公開され始めたら自動でリンクを足す（過去セッションも遡って）

---

## 9.4【P1】データの更新頻度・遅延の表示

- 現状フッタ／ヘッダに「最終更新」が出ない（ダッシュボード概要のみ）
- 「**○時間前に更新／次回更新は約○時間後**」のような表現があると、サイトが息をしている感じが伝わる

### 改善案
- ヘッダ右上に小さく「直近更新: 6時間前」（hover で正確な時刻）
- ダッシュボード以外のフッタにも `lastUpdated` を表示
- バッチが失敗していたら `データ更新が滞っています` の警告を出す（Healthcheck JSON を `/api/health.json` で生成）

---

## 9.5【P1】訂正・誤字・話者誤判定の報告動線

### 現状
- 「報告する」ボタン・リンク無し
- 誤字（Whisper の誤認識）や話者誤判定（speaker_tagger の誤り）を見つけても、ユーザーは諦めるか SNS で晒すしかない

### 改善案
1. 各 Q&A カード右上に `⋯` メニュー → 「誤りを報告」
2. クリックで GitHub Issue テンプレート or Google Form にプリフィル（セッション ID、Q&A ID、ユーザーが選択したテキストを含む）
3. issue ラベル `correction-request` で分類し、運営側のトリアージ動線へ

---

## 9.6【P1】ライセンス明示

`ARCH.md` で示唆されている「公的記録のオープン化」コンセプトに対し、ユーザーが**何の条件で再利用できるか**が UI に書かれていない。

### 改善案
- フッタに `データ: CC BY 4.0 ／ コード: MIT` のような明示
- TSV エクスポート時、TSV 先頭にコメント行で出典・ライセンスを焼き込む
- API JSON ファイルのトップに `license`, `attribution` フィールドを足す

---

## 9.7【P1】LLM モデルバージョンの表示

### 現状
- `metadata.json` に `whisper_model`, `llm_model` が入っている（`deepseek-ai/DeepSeek-V3.2`）
- UI には出ない

### 改善案
- セッション詳細の出所リンクの並びに「処理: Whisper L-v3-turbo / DeepSeek V3.2」を小さく表示
- methodology ページに「モデル変更履歴」を残す
- モデル変更前後で評価値が大きく変わる場合は、UI 側で `※モデル更新により再評価された旧データ` のような注記を出す

---

## 9.8【P2】記事引用・SNS シェア時の見栄え

[07 章 7.10](07-session-detail.md) と重複。本ページの観点では、**シェアされた先で誤解されない**ことが重要。

### 改善案
- OG image に「LLM 自動要約」を必ず焼き込む
- Twitter/X カードの `description` に出所サイト名を含める

---

## 9.9【P2】個人発言の保存・追跡

- 政治家本人や事務所が「○年前の発言を消したい」と要請するケースがあり得る
- 公的記録の引用範囲なので原則応じる必要は無いが、対応方針を `/about/terms` に明記しておくと炎上リスクが下がる

---

## 9.10【P2】問い合わせ集計のメタ表示

- `data/.../utterances.json` にラベル付けする際、ユーザー報告で訂正された箇所を `manual_correction: true` で記録
- セッション詳細に「ユーザー貢献で訂正された箇所: 3 件」のメタを表示すると、コミュニティ参加感が高まる
