# 01. ペルソナと利用シナリオ

[← 戻る](README.md)

衆議院本格稼働後を見据えると、想定ユーザーが大きく広がる。
本サイトの UX 判断は「誰がどの瞬間に何を達成したいか」を軸に置く必要がある。

以下、主要 7 ペルソナと、それぞれの 1〜2 個の典型タスク、現状サイトでの詰まり所を列挙する。
（**詰**＝Pain Point、**勝**＝Already Working、**機**＝機会／伸びしろ）

---

## P1. 関心ある一般市民「子育て中の有権者・西田さん（38）」

- **目的**: 自分が支持する／気になる議員が、保育・教育で何を発言したか確かめたい。テレビでは流れない発言を 5 分で読みたい。
- **使い方**: スマホ／通勤の短時間。検索ボックス → 議員名で絞り込み → 要約をスクロール。
- **詰**: モバイルで `/browse` を開くと、フィルタ全部が広がっており（[08 章](08-mobile-accessibility.md)）、結果まで指 3 回スクロール。
- **詰**: 検索結果ラベル `[Q&A]` `[概要]` `[発言]` の意味が分からない。
- **詰**: 「回避度 中（55%）」が何を意味するのか分からず、政治的な印象操作に見える可能性。
- **勝**: Q&A カードが「質問 ─ 答弁」の二段組で、要約が箇条書きで整理されているのは強み。
- **機**: 「この議員をフォロー」（後で更新を確認）が現状ない。

## P2. 政治記者「全国紙・社会部 武田さん（42）」

- **目的**: 直近 1 週間の主要委員会で「○○法案」に絡んだ大臣答弁を漁り、評価が割れる発言や約束事項を抽出する。
- **使い方**: PC、複数タブ。一覧で日付＋大臣＋トピックを絞り、TSV で Excel に流す。
- **詰**: 「関連法案」フィルタはあるが、ホーム・セッション詳細の法案タグからは詳細ページがなく、法案ごとの審議横串が組めない。
- **詰**: TSV エクスポートは便利だが、列定義（CSV ではなく TSV である理由・列名）の説明がなく、Excel で文字化けする可能性。
- **詰**: 「約束トラッカー」の status は常に `unverified`（未確認）固定で、「実際に守られた／約束済み／検討中」の進捗追跡になっていない。
- **勝**: 各 Q&A に動画タイムスタンプ付きリンクがあり、引用するときに直接該当秒へ飛べる。これは商業メディアにとって極めて価値が高い。
- **機**: 「同じ約束を別の委員会で再質問された」トラッキング（議員別ピボット）。

## P3. 国会議員秘書／野党調査チーム「○○議員事務所・佐藤さん（30）」

- **目的**: 自分の議員が次回質疑で使うため、過去 3 ヶ月の閣僚答弁から「論点ずらし」「未回答」のパターンを抽出する。
- **使い方**: PC。発言者で絞り、回避度高をハイライトして全文を確認、出典 URL とタイムスタンプをセットで控える。
- **詰**: 「回避度」の閾値・算出根拠が示されていないので、内部資料に転記しづらい。
- **詰**: 発言者の名寄せが弱い（例: `牧野大臣` と `牧野たかお` が別レコードになりうる）。
- **詰**: 検索結果に `[Q&A]` を多く返したいのに、現状は概要・Q&A・発言が混在する。
- **勝**: Q&A の `commitment_text` が独立フィールドとして抽出されている点は使える。
- **機**: 「議員 A の質問に対する閣僚 B の答弁だけを時系列に並べる」ピボット。

## P4. 政策研究者・大学院生「政策大学院生 林さん（27）」

- **目的**: 「防災庁設置法案」の審議過程を博士論文の事例として集める。発言全文の可検索性、引用の再現性が必要。
- **使い方**: PC。データを CSV/JSON でダウンロードして自前分析。
- **詰**: 一括 JSON / CSV ダウンロードがない（TSV は filter 結果のみ・最大 PAGE_SIZE × フィルタ）。
- **詰**: バージョン情報・更新日時がフッタにもない（dashboard だけにある `lastUpdated`）。
- **詰**: トピック分類が「広域 829 個 vs 狭域 6,286 個」で重複が大きく、カテゴリ集計に使いにくい（[02 章](02-cross-cutting-issues.md)）。
- **機**: API ドキュメント／OpenAPI スキーマ／CC ライセンス明記。

## P5. 海外記者・在京特派員「Reuters 東京支局 Tom さん（45）」

- **目的**: 安全保障・通商の議論を英語で素早く把握。日本語で読むスピードに限界。
- **詰**: UI が完全に日本語のみ。ロゴ・ナビ・委員会名・要約まで全部日本語。Google 翻訳をブラウザに頼ると、Recharts や React 島の動的テキストが翻訳されない。
- **詰**: 委員会名が読めない（"消費者問題特別委員会" 等）。
- **機**: 委員会名・ナビ・主要要約のみでも英語併記すれば、参入障壁が大幅に下がる。

## P6. 高齢市民・スクリーンリーダー利用者「視覚障害者・松本さん（68）」

- **目的**: 関心法案の審議内容を耳で追いたい。動画よりも要約読み上げで効率的。
- **詰**: ヒートマップ・タイムライン SVG に ARIA ラベル／代替テキストがほぼ無い。
- **詰**: チェックボックスは label 付きで OK だが、トグルボタンの状態（`aria-pressed`）が一部欠落。
- **詰**: 配色のコントラスト比は概ね良好だが、回避度の赤・黄・緑は色覚異常者には判別困難。
- **勝**: ボタンがほぼ全て `<button>` 要素になっており、キーボード操作可能。
- **機**: 全文を ARIA `region` でラベル付け、スキップリンクの追加。

## P7. プロダクト運営者・ボランティア開発者「OSS 貢献者・あなた」

- **目的**: 拠出データの整合性を CI で守りつつ、ノイズ（不明委員会・1 件しかない発言者）を後処理で除去したい。
- **詰**: `data/` の Q&A データに `qa.topic`（狭域）と `entry.topics`（広域）が併存し、フィルタ／ヒートマップ／検索が暗黙の前提でぶつかる。
- **詰**: 委員会名 `不明` が混入したまま heatmap に出る。
- **詰**: stats.json の `avgEvasionScore` がサンプルサイズ重み無しの単純平均で、論文・記事に引用されるとリスク。
- **機**: スクリプト `generate-api.ts` に "意味のあるサンプルサイズ" のしきい値を一箇所で持たせるリファクタ。
