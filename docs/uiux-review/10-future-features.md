# 10. 拡張機能（Tier 1 含む）

[← 戻る](README.md)

本格稼働のあとに価値を伸ばすための機能候補。
コア体験の P0 / P1 が片付いてから着手する前提で、ペルソナ別に並べる。

---

## 10.1 一般市民（P1）向け

### 10.1.1 「フォロー」機能（ローカル）

- お気に入り議員 / 委員会 / トピックを localStorage に保存
- ホーム上部に「あなたがフォロー中」セクション
- データ更新時、新しい該当セッションがあれば「未読 3 件」バッジ
- 静的サイトでも実装可能（サーバー不要）

### 10.1.2 「読みやすさモード」

- 行間広め・大きめフォント
- ダーク／ライト切り替え（システム連動 + 明示切替）

### 10.1.3 用語ヘルプ

- ホバーで「副大臣とは」「政府参考人とは」のミニヘルプ
- 委員会の役割（"環境委員会で扱うもの"）の 1 行説明

---

## 10.2 政治記者・議員秘書（P2/P3）向け

### 10.2.1 比較ビュー

- 議員 A vs 議員 B: 同じ法案・同じトピックでの発言を並べる
- 委員会 A vs 委員会 B: 同じ法案を扱った 2 つの委員会の質疑差分
- 月別 / 週別の発言量・回避度・コミットメント数の推移

### 10.2.2 法案ページ

- `/laws/:law_id` で法案ごとの審議横串
- 提出から成立までのタイムライン
- 採決結果（賛成・反対）
- 関連 Q&A 全件
- LawEntry に `progression: [proposed, committee, plenary, passed]` を追加

### 10.2.3 同一発言検出

- 議員 A が複数委員会で似た質問を繰り返している
- 答弁者 B が異なる質問者に対して同じ約束を複数回している
- 全文の単純コサイン類似度 + LLM 意味類似度のハイブリッドで実装

### 10.2.4 「約束の追跡」自動化

- 過去の `commitment_text` を時系列で並べ、後の答弁で同じトピックに触れた時に `restated` 候補を提示
- ユーザーが手動で `realized / not_yet` をマーク（GitHub-backed の collaborative editing）

### 10.2.5 議員レーダーチャート

- 議員 1 人につき: 発言量／質問数／約束数／平均回避度／対応大臣バリエーション
- 政党平均との比較を重ねる

## 10.3 研究者・データ系（P4/P7）向け

### 10.3.1 公式 API ドキュメント

- 現状の `/api/*.json` は build artefact だが、利用可能な公開エンドポイントとして文書化
- スキーマを `/api/schema.json` で公開
- バージョン管理（`v1`, `v2`）

### 10.3.2 一括ダウンロード

- フィルタ結果ではなく「全データセット zip」を `releases` に毎月公開
- `data-2026-04.zip`（200MB 程度）

### 10.3.3 引用フォーマット

- 各 Q&A に「引用形式コピー」ボタン:
  - APA 風: `衆議院 災害対策特別委員会（2026年4月23日）, Q&A qa_001, 国会議事録リアルタイムDB, 取得日: ...`
  - DOI / ArchiveBox 連携の検討

---

## 10.4 海外記者（P5）向け

### 10.4.1 機械翻訳済みサマリ

- ビルド時に `summary.session_summary` を英訳
- 委員会名・議員名のローマ字表記
- `/en/...` 配下に並走サイト

### 10.4.2 主要トピックの英語キャッシュ

- 「防災庁設置法案」など、海外読者が日本語で検索できないキーワードを英訳キーで紐付け
- 検索ページで `disaster prevention agency` → `防災庁` への自動リダイレクト

## 10.5 Tier 1（BYOK / OpenRouter）

`ARCH.md` Phase 6 に書かれた構想を UI に落とすときの提案。

### 10.5.1 設定画面

- `/settings` 既存ページを再構築:
  - キー入力（sessionStorage 保存、サーバー送信なし、を明記）
  - モデル選択ドロップダウン
  - 「現在のセッション中のみ有効」表示
  - 「お試し用に小モデル」のリンク

### 10.5.2 アンロックされる機能（一例）

- **動的要約再生成**: 保存された要約に満足できない場合、ユーザーキーで再生成
- **比較質問**: 「この答弁と先週の答弁を比較して」
- **批評モード**: 「この答弁は質問にどう答えていないか説明して」
- **ユーザー独自の評価軸**: 「経済政策の具体性」「実施期限の明示性」など、ユーザーが評価項目を定義
- **会話型インターフェース**: 「2026 年 4 月の高額療養費に関する答弁を要約して」

### 10.5.3 Tier 0/1 の境界の見え方

- Tier 1 機能が必要な箇所に「✨ AI 分析（要 API キー）」のラベル
- キー未設定時はクリックで `/settings` に遷移
- Tier 0 で見られる範囲を狭めず、Tier 1 は**追加価値**として位置付ける

## 10.6 コミュニティ機能

### 10.6.1 コメント・注釈

- 各 Q&A への注釈を GitHub Discussions / Issue ベースで集約
- 「このサイトに記載された訂正一覧」公開ページ
- 寄稿者バッジ（GitHub プロフィール連携）

### 10.6.2 関連リンク収集

- 各 Q&A に外部記事・ブログ記事へのバックリンクをコミュニティで追加
- スパム対策のためモデレーション必須

---

## 10.7 通知・購読

### 10.7.1 RSS / Atom フィード

- ホーム最新 50 件
- 議員別フィード（`/api/speakers/:name/feed.xml`）
- 委員会別 / 法案別

### 10.7.2 メール / Slack 通知

- BYOK 拡張で、フォロー中の議員が新たに発言したらフックを送る
- 静的サイト範囲を逸脱するので Tier 1 寄り

---

## 10.8 検索・分析の高度化

### 10.8.1 ファセット検索

- Pagefind に `committee`, `chamber`, `evasion_score`（bins） などのファセットを定義
- 検索結果と /browse の体験を統合

### 10.8.2 トピック共起ネットワーク

- 同セッションで一緒に語られるトピックの D3 force-directed
- 党派ネットワーク（誰が誰に質問しているか）
- 既に依存関係に `d3-force` が入っているので、ツールチェーンは揃っている

### 10.8.3 引用関係グラフ

- 議員 A が議員 B の発言を引用 → 矢印
- 政府答弁が過去答弁を踏襲しているか → タイムライン

---

## 10.9 運用・モニタリング

### 10.9.1 ヘルスチェック

- `/api/health.json`: 最新バッチの実行時刻、成功/失敗、未処理セッション数
- ダッシュボード上部にステータスバー

### 10.9.2 利用統計

- Cloudflare Web Analytics や Plausible（プライバシー配慮）を入れて、どの機能が使われているかを把握
- ダッシュボードの利用率が低いことを定量化
