# 03. 情報設計とナビゲーション

[← 戻る](README.md)

ご指摘の通り、ホーム・一覧・セッション詳細のフィルタ実装が重複しているのが最大の構造問題。本章はナビゲーション全体・URL 設計・ページ間の役割分担を扱う。

---

## 3.1【P0】「ホーム」「/browse」「セッション詳細フィルタ」の 3 重実装

### 現状の差分

| 画面 | 実装 | 状態管理 | データソース | フィルタ軸 |
|------|------|---------|------------|----------|
| `index.astro`（ホーム）| Astro SSR | なし | `getAllSessions()`（metadata.json 直読み） | 日付グルーピングのみ |
| `browse.astro` → `FilterPanel.jsx` | React 島 (client:load) | URLSearchParams + useState | `/api/index.json` ほか 5 エンドポイント | 院・日付・委員会・政党・発言者・役割・トピック・関連法案 |
| `[chamber]/.../[slug].astro` | Astro + 内部 `<script>` | URL ハッシュ `#speaker=...&topic=...` + DOM 直接操作 | ビルド時 props | 発言者・トピックのみ |

### 何が重複しているか

1. **「Q&A カードを並べて、属性で絞り込み、件数を表示する」**コアロジックが 3 通り。
2. **発言者ボタン／トピックボタン**の見た目（`.speaker-filter-btn`, `.topic-filter-btn`）が、セッション詳細では Astro 側で再実装されている。
3. **URL 管理**が片方クエリ、もう片方ハッシュ。記者が URL を共有するときに混乱する。

### 何が違うべきか
- ホーム = 「最近 N 日の議事カードリスト」（**サマリ閲覧**）
- /browse = 「全件横断のフィルタ＋検索結果」（**深掘り**）
- セッション詳細 = 「1 つの会議の中をスクロール／絞り込み」（**精読**）

特にセッション詳細の「発言者で絞り込む」「トピックで絞り込む」は、ページ内ハイライトに過ぎない。/browse の発言者・トピック絞り込みは、サイト全体から該当 Q&A を引く。**この性質の違いを UI でも見せる**べき。

### 改善案

#### 案 A: フィルタコンポーネントの統合（推奨）
1. `FilterPanel.jsx` を `<QAFeed>` に名前変更し、props で「対象データセット（all / single-session）」と「URL パラメータ前提（query / hash）」を切り替える。
2. セッション詳細では、対象データセットを「このセッションの qa_pairs」に固定して `<QAFeed>` を埋め込む。発言者・トピックボタンのクリック → `<QAFeed>` の state を更新。
3. ホームは `<QAFeed>` の "showFilter=false&groupBy=date" モードで使う（pagination off, 最新 7 日）。
4. 結果: 1 つのコンポーネント、1 つのフィルタ仕様、1 つの URL 設計、1 つのテストでメンテ。

#### 案 B: セッション詳細はそのまま Astro、ただしデザイン共通化
- 共通の `<QACardsLayout>` Astro コンポーネントを作って、見た目は揃える。フィルタロジックは別だが、CSS と機能を一致させる。
- 案 A より低コストだが、長期的には負債が残る。

## 3.2【P1】グローバルナビが「最初に何をすべきか」を示していない

### 現状
ヘッダ: `🏛 国会議事録DB ＞ 一覧 ／ 検索 ／ ダッシュボード`

- ホームは独立したリンクが無く、ロゴがホーム遷移を兼ねる。
- 「一覧」「検索」「ダッシュボード」は内容が想像しづらい：初回訪問者は「何の一覧？」「何が違うの？」となる。
- 「ダッシュボード」をクリックするとサブタブが 4 つ（概要／トピック分析／約束トラッカー／発言者分析）。階層が深い。

### 改善案
1. ナビをユーザーが達成したいタスクで命名:
   - 「最新の審議」（旧ホーム）
   - 「絞り込んで読む」（旧 /browse）
   - 「全文検索」（旧 /search）
   - 「全体分析」（旧 /dashboard）
2. ホームにヒーロー領域を 1 つ作り「3 つの入口」を示す:
   - 大きな日付検索ボックス（"2026-04-23 の審議を見る"）
   - 議員名のオートコンプリート
   - 委員会のクイック選択
3. ロゴ脇に「いまの会期: 第 217 回（2026/01/24〜）」など、文脈を表示。

## 3.3【P1】ホームが「日付グルーピング」だけで、絞り込み手段がない

スクリーンショット `screenshots/20-home-aboveFold.png` を参照。140 セッションが日付見出しの下に縦並び。1 日に 10 委員会が並ぶこともあり、デスクトップでも縦に長い。

### 詰まり所
- 院（衆／参）の切り替えがない（本格稼働後はさらに 2 倍に）。
- 委員会の表示順（「総務委員会 → 環境委員会 → ...」）が都度違って見える（実は `getAllSessions()` のソート順次第）。
- 「気になる委員会だけ表示」「特定法案関連だけ」が出来ない。

### 改善案
- ヘッダ直下に「全て / 衆 / 参」「過去 7 日 / 30 日 / 全期間」「お気に入り委員会」のクイックフィルタチップを追加。
- カードを「重要度ソート」できるよう、Q&A 数・約束事項数・スピーカー数で並べ替えオプションを置く。
- もしくは、ホームは「ハイライト 5 件」「日次サマリ 1 段落」に振り切り、深掘りは /browse に流す（[10-future-features.md](10-future-features.md) 参照）。

## 3.4【P1】レイアウト幅が画面間で違う（960px ↔ 1100px）

`BaseLayout.astro`: `main { max-width: 960px; }`
`DashboardLayout.astro`: `main { max-width: 1100px; }`

ナビをクリックして移動するとコンテンツの幅が動いて見える。

### 改善案
- レイアウトを 1 つに統合し、コンテンツ最大幅を 1080–1100px で揃える。
- ヒートマップなど横長コンポーネントは内部で `overflow-x: auto` を持っているので、共通幅で問題ない。

## 3.5【P2】URL の永続性

- /browse は state を `replaceState` で URL に同期 → 履歴が汚れない。これは正解。
- 一方で「ブラウザバック」した時にもフィルタが復元されるよう、`pushState` ベースのオプションも検討余地あり。
- セッション詳細の `#speaker=...&topic=...` は、リンク共有しても先方で展開されない場合がある（CSP・SNS プレビュー）。クエリベースに寄せるのが安全。

## 3.6【P2】settings ページが本番に出ている（プレースホルダ）

```html
<p>Phase 6でBYOK（OpenRouter APIキー）設定が追加される予定です。</p>
```

- 一般ユーザーには「Phase 6」が分からない。
- リリース前に `nav` から外す or 「準備中」として明示的にデザインする。

## 3.7【P2】フッタの出所リンクが常に衆＋参の両方

- 現在は参議院データが空でも、フッタは `衆議院TV ／ 参議院TV` の両方を出している。
- `lastUpdated` も含めてフッタを「サイト主体・更新時刻・出所」のセットに整理したい。

出所: 衆議院インターネット審議中継 ／ 参議院インターネット審議中継
データ最終更新: 2026-04-29 02:02 JST
このサイトについて ｜ 方法論 ｜ 利用規約 ｜ 連絡
