# 05. 「回避度」では質疑の良し悪しが見えない問題

[← 戻る](README.md)

> **本章の射程**
> 当初の論点は「回避度の表示が分かりにくい・法的リスクがある」だった。実データ（衆議院 140 セッション・6,308 Q&A ペア）を確認したところ、より根本的な問題が浮かび上がった ── **現行の「回避度」一指標では、質疑の良し悪しがほとんど判別できない**。
>
> 本章では (1) なぜ「回避度」だけでは足りないか、(2) どのような多軸指標に置き換えるべきか、(3) UI と方法論の整理、の順で提案する。**実装はまだ着手しない**。設計合意のためのドラフト。

---

## 5.1 現状の指標と、何が物足りないか

### 5.1.1 現状の表示と算出ロジック

- **表示**: Q&A カードに「回避度 中（55%）」/ 低（緑）・中（橙）・高（赤）のバッジ
- **算出**（`structurer.py:76-81`）: DeepSeek V3.2 に答弁文を渡し、以下の目安で 0.0–1.0 を出力させる
  - `0.0–0.2`: 具体的な数値・事実で回答
  - `0.3–0.5`: 一般論で回答、具体性に欠ける
  - `0.6–0.8`: 質問をはぐらかす、別の話題にすり替える
  - `0.9–1.0`: 完全に回避、「答えられない」等
- **集計**（`generate-api.ts`）: `clearCount` < 0.3 / `hedgingCount` 0.3–0.7 / `evasiveCount` ≥ 0.7

### 5.1.2 実データ分布（2026-04 時点、衆議院 140 セッション）

| 区分 | 件数 | 割合 |
|---|---|---|
| 全 Q&A ペア | 6,308 | 100% |
| 回避度 < 0.3（明確） | 3,374 | 53.5% |
| 0.3 ≤ 回避度 < 0.7（含み） | 2,444 | 38.7% |
| 回避度 ≥ 0.7（回避的） | 490 | 7.8% |
| 平均回避度 | 0.295 | — |

質問 intent の分布: `information_request` 2,642 / `policy_proposal` 2,374 / `accountability` 661 / `fact_check` 605 / その他 26。

### 5.1.3 「役に立っていない」の正体

実データを 50 件サンプリングして読み比べると、現行スコアの限界が 4 点見える。

1. **答弁側しか採点していない。** 「良い質疑か」は質問の作り込みで半分以上決まる。直接性しか測らないと、「論点不明確で要点が散った質問に、官僚が無難に返した」ようなペアが、低スコア（=「明確な回答」扱い）として埋もれる。
2. **「直接性」と「価値」が無関係なケースが多い。** 例えば本サンプルの「不適正取締りの端緒は何か」Q&A は回避度 0.1 だが、これは事務的な事実確認であって議事録に残す価値はほぼゼロ。一方、回避度 0.7 の「再審手続きの遅延理由を問う」答弁は、確かにはぐらかしているが、**そのはぐらかし自体が記録され、次の追及の出発点になる**点で重要な質疑である。直接性が低いから価値が低い、とは限らない。
3. **「コミットメントの強度」が消えている。** `has_commitment` は bool 一つ。「努めてまいります」「真摯に取り組む」（精神論）と「○月までに検討会を設置し公表する」（期限付き行動約束）が同じ「約束あり」として扱われる。後者こそ「ネクストアクションを答えざるを得ない問い」の成果物のはずだが、現行 UI では区別不能。
4. **「新規性／議事録価値」が完全に欠落している。** 既存答弁の貼り付けで終わったのか、新解釈・新数字・新たな立証責任の転換を引き出したのかが、スコアにも UI にも現れない。質問品質を 4 段階（前提誤り／根拠不明／良いが新規性なし／的を射た新規指摘）に切り分ける際の上位 2 段階が、現行スコアでは同一視されてしまう。

> **要約**: 「回避度」は「答弁が論点に直接触れたか」の局所判定としては概ね機能している（実データ上でも、はぐらかし度合いと相関した値を返している）。だが、**質疑が国民・他議員・省庁にとって価値があったか**という上位判断には、ほとんど寄与していない。

## 5.2 設計指針: 「良い質疑」を多軸で捉える

議会研究の一般的観点（議会質問の "salience × specificity" を扱う研究系統や、英国 Hansard Society の Question Quality framework 等）を踏まえると、良い質疑の価値は単一軸に圧縮できない。最低でも **質問側 / 答弁側 / ペアとしての帰結** の 3 レイヤーに分けて評価すべき。

### 5.2.1 設計原則

1. **正の方向で測る。** 「回避度」のような負の語ではなく、「直接回答度」「具体性」「コミットメント強度」など正の語で揃える。負の評価は引き算で表現する（高スコア = 良い、で揃える）。
2. **質問と答弁は別軸で評価する。** 良い答弁が引き出せたかは、質問の良さと答弁者の姿勢の合成。これを 1 つの数値に潰さない。
3. **「議事録価値」は別レイヤー。** 個別の Q&A スコアとは独立に、「この質疑はあとで引用される可能性が高いか」を見るレイヤーを設ける（後述 5.5）。
4. **LLM 判定であることを常時明示する。** 全指標に「LLM 自動評価」のラベルを付ける。決定論的に出る指標（文長、数値の含有数など）は別ラベル「機械集計」で扱い、混同しない。
5. **党派色を出さない。** 指標セットは中立に揃え、特定政党の政策観や立場（マニフェスト連動度、特定領域への寄与など）は **付帯指標** として本サイト本体とは分離する。

### 5.2.2 指標体系の全体像

```
┌─ 質問の質（Question Quality, QQ） ──────────────┐
│  QQ-1 論点明確度  (Clarity)                     │
│  QQ-2 具体性・一次ソース密度 (Groundedness)     │
│  QQ-3 新規性 (Novelty)                          │
│  QQ-4 当事者性 (Stakeholder salience)           │
│  QQ-5 行動要求度 (Actionability)                │
└─────────────────────────────────────────────────┘
┌─ 答弁の実質度（Answer Substantiveness, AS） ────┐
│  AS-1 直接回答度 (Directness)  ← 旧「回避度」逆 │
│  AS-2 具体情報量 (Information density)          │
│  AS-3 新答弁度 (Beyond-precedent)               │
│  AS-4 コミットメント強度 (Commitment strength)  │
└─────────────────────────────────────────────────┘
┌─ ペア／セッションの帰結 (Outcome) ──────────────┐
│  OC-1 議事録価値 (Record value)                 │
│  OC-2 追及深度 (Probing depth, follow-up あり時)│
│  OC-3 引用可能性 (Quotability)                  │
└─────────────────────────────────────────────────┘
```

「全体総合スコア」は出さない。各カードに **2〜3 個の主要バッジ + 詳細展開** という UI に倒す（5.6 参照）。

## 5.3 質問の質（QQ） ─ 5 指標

質問は **作り込みで決まる部分が大きい**。論点選定・質問設計に関わる一般的な観点を、LLM が判定可能な粒度に落とし込む。

### QQ-1 論点明確度 (Clarity)  `0.0–1.0`
**定義**: 「何を確認したいのか／何を引き出したいのか」が一文で言えるか。

- 判定: LLM に質問 full_text を渡し、「この質問が何を確認しようとしているか、25 字以内で 1 つに言い切れるか」を生成させ、自己整合性スコアと長さで判定。複数論点を 1 質問に詰め込んでいる場合は減点。
- 機械集計の併用: 文数・疑問符の数・接続詞の頻度を併記。

### QQ-2 具体性・一次ソース密度 (Groundedness)  `0.0–1.0`
**定義**: 質問の前提が 1 次ソース（政府統計・法令・過去答弁・当事者団体データ）に立脚しているか。

- 判定: 質問 full_text 中の「数値」「固有団体名」「法令番号」「日付」「過去答弁の引用」の出現を LLM + 正規表現で抽出し、密度を算出。
- 加点要素: 大きな数字を生活実感に翻訳する表現（例: 年間総額を一人当たり月額・日額に分解する、馴染みのある単価と比較する等）を検出した場合に加点。

### QQ-3 新規性 (Novelty)  `0.0–1.0`
**定義**: 過去国会で同じ問いが既に立てられていないか。既出の場合は「前回答弁から状況が変わった点」「残った宿題」を起点にしているか。

- 判定: Pagefind / `data/laws` および会議録 RAG（過去 N セッション分の質疑インデックス）に対して類似検索し、最近接の既出 Q&A の類似度を取る。低類似度 → 高新規性。
- 完全な新規性判定は将来課題（国会会議録 API との連携が必要）。当面は **本サイト内で見える範囲の既出度** に限定し、その旨を明記する。

### QQ-4 当事者性 (Stakeholder salience)  `0.0–1.0`
**定義**: 当事者の顔が浮かぶ質問か。制度・数字を語るだけでなく、その制度のもとで暮らしている人の状況が見えるか。

- 判定: LLM に「この質問に登場する当事者カテゴリ」を抽出させる（例: がん患者、高齢者、特定地域住民、特定業種事業者）。抽象度（「国民全体」「事業者全般」）が高いほど低スコア、具体度（「○○県の産科医院」「治療開始後 3 割の所得減を訴えるがん患者団体」）が高いほど高スコア。

### QQ-5 行動要求度 (Actionability)  `0.0–1.0`
**定義**: 答弁者がネクストアクションまで答えざるを得ない設計になっているか。

- 判定軸:
  - Yes/No 型の問いか（「検証し公表いただけますか」）
  - 期限が区切られているか（「○月までに」）
  - 選択肢が提示されているか
  - 立証責任の転換を含むか（「その懸念に確からしい根拠はあるのか」）
- 機械集計併用: 文末の助動詞（「いただけますか」「ご答弁ください」「お示しください」）パターン。

### 質問 intent の整理（既存 `intent` フィールドと連動）

現行の `intent` フィールド（fact_check / policy_proposal / accountability / information_request / other）は維持。各 intent ごとに「期待される質の重心」が違う点を UI で明示する:

| intent | 重視軸 |
|---|---|
| fact_check | QQ-2 具体性／QQ-1 明確度 |
| policy_proposal | QQ-5 行動要求度／QQ-4 当事者性 |
| accountability | QQ-1 明確度／QQ-3 新規性 |
| information_request | QQ-2 具体性 |

## 5.4 答弁の実質度（AS） ─ 4 指標

旧「回避度」の置き換え。直接性だけでなく、情報量・新規性・コミットメントの 4 軸で見る。

### AS-1 直接回答度 (Directness)  `0.0–1.0`  ← 旧「回避度」を反転
**定義**: 質問の主題に直接触れているか。

- 旧「回避度」の判定基準を **正方向に反転** して維持（高 = 良い）。
- 既存スコアとの互換のため、内部では `directness = 1 - evasion_score` として算出可能。
- ラベル: 5 段階（直接 / 概ね直接 / 部分的 / 一般論 / 触れていない）。中央値に寄せる正規化を入れ、極端値を出にくくする。

### AS-2 具体情報量 (Information density)  `0.0–1.0`
**定義**: 数値・固有名詞・期限・根拠が答弁内にどれだけ含まれているか。

- 機械集計: 全角数字・年月日・%・円・件・人 などの抽出件数 / 答弁文長で正規化。
- LLM 判定: 「具体名・数値・期限・根拠の引用」のうち含まれるカテゴリを 0–4 でカウント。
- 既存「回避度 0.0–0.2: 具体的な数値・事実で回答」の判定基準を、この指標に切り出す。

### AS-3 新答弁度 (Beyond-precedent)  `0.0–1.0`
**定義**: 既存答弁の貼り付けで終わったか、新しい解釈・数字・方針を引き出したか。

- 判定: 過去会議録 RAG への類似検索で、答弁文と最近接過去答弁の類似度を取る。
- 高類似（=「定型答弁」）→ 低スコア。低類似 → 高スコア。
- 当面は本サイト内のセッション集合でのみ判定し、限界を明記。
- 質問品質レベル分類における「既出論点の繰り返し」と「新規性のある指摘」を分ける軸。

### AS-4 コミットメント強度 (Commitment strength)  `0–4` 段階
**定義**: 答弁から引き出した約束がどの程度具体的か。

| Lv | 定義 | 例 |
|---|---|---|
| 0 | 約束なし | 「現状を申し上げると…」のみ |
| 1 | 努力義務的 | 「努めてまいります」「真摯に取り組む」 |
| 2 | 検討約束 | 「検討してまいります」 |
| 3 | 行動約束 | 「検討会を設置いたします」「次回までに整理します」 |
| 4 | 期限付き行動約束 | 「○月までに公表します」「来年度予算で計上します」 |

- 既存 `has_commitment: bool` を **置き換え**。`commitment_text` は維持しつつ Lv を併記。
- ダッシュボードの「約束事項数 502」は Lv 別に内訳表示する。
- Lv 3 以上のみを「フォローアップ対象」として抽出するための DB スキーマ拡張を別途検討（引き出した検討事項を横断的に追跡できる仕組み）。

## 5.5 ペア／セッションの帰結（OC） ─ 3 指標

個別 Q&A の Q 側・A 側スコアとは独立に、「**この質疑があとで参照される可能性が高いか**」という上位の指標を設ける。「議事録に事実・解釈・前進を残す」という質疑の核心的な役割に対応する。

### OC-1 議事録価値 (Record value)  `0.0–1.0`
**定義**: この Q&A が将来、他議員・省庁・メディアに引用される可能性が高いか。

- 構成要素（合成スコア、各重みは要調整）:
  - **法解釈ピン留め**: 法案の「標準的な費用」「適切な配慮」等の曖昧表現に対して、政府の解釈見解を確定させたか
  - **数字・事実の確定**: 政府が公的な数字を答弁で確定させたか
  - **新答弁度（AS-3）の取り込み**: 既存方針を超える答弁を引き出した場合に高得点
  - **総理・大臣答弁か**: 答弁者の役職重み（大臣 > 副大臣 > 政府参考人）
- 表示: 「議事録価値: 高（このセッションでも上位 5%）」のような **相対表現** を主にし、絶対値の数字を前面に出さない。

### OC-2 追及深度 (Probing depth)  `0.0–1.0`
**定義**: follow-up 質問が連鎖し、最初の答弁から踏み込んだ回答に至ったか。

- 判定: 既存 `follow_up_ids` を活用。チェーン長と、チェーン内での AS-1（直接回答度）・AS-4（コミットメント強度）の最大値の伸び幅を計測。
- 「最初の答弁では Lv1 努力義務だったが、追及で Lv3 行動約束まで引き上げた」ようなケースに高スコア。
- 答弁パターンを想定したうえで再質問の方向を見立てる「展開予測型」の質疑設計を評価する軸。

### OC-3 引用可能性 (Quotability)  `0.0–1.0`
**定義**: メディア・他議員にとって切り取りやすい一文を含んでいるか。

- 機械集計: 答弁・質問の中から、長さが適度で（30–80 字）、固有名詞・数字を含み、語尾が断定的な文を抽出。
- LLM 判定: 「この Q&A から 1 文を引用するなら、最も力のある一文はどれか」を抽出させる。
- 表示: 抽出された候補文をハイライトし、コピーボタンを置く（10 章「将来機能」と連動）。

### Outcome 指標の使いどころ

- セッション詳細ページに「**このセッションの注目 Q&A**」セクションを置き、OC-1 上位 3 件を表示。
- ダッシュボードの「ヒートマップ」を、平均回避度ではなく **議事録価値の総和 / セッション** に置き換える。
- 「コミットメント追跡」ページは Lv3 以上のみを母集団として、約束 → 実行のフォローアップ追跡に使う。

## 5.6 UI への落とし込み

### 5.6.1 Q&A カード（改善後イメージ）

```
─────────────────────────────────────────────────────────
🏷  topic: 高額療養費制度の見直し                  [intent: policy_proposal]
─────────────────────────────────────────────────────────
❓ 質問 ─ ○○議員（××会派）
   ├ 論点明確度    ●●●●○  明確（一論点）
   ├ 具体性        ●●●●●  数値・団体データを引用
   ├ 当事者性      ●●●●○  特定の患者団体に紐づく
   └ 行動要求度    ●●●○○  価値判断を迫る形

💬 答弁 ─ ○○大臣
   ├ 直接回答度    ●●●○○  概ね直接（一部一般論）
   ├ 具体情報量    ●●○○○  数値の引用なし
   ├ 新答弁度      ●●●●○  既存方針を超える解釈を提示
   └ コミットメント Lv3 行動約束「検討会で論点整理を行う」

📌 議事録価値: 高（このセッション上位 10%）  ⓘ LLM 自動評価
🔗 引用候補: （答弁中の最も力のある一文を自動抽出）
─────────────────────────────────────────────────────────
```

- バッジは **5 段階の○●表示** に統一（数値の前面化を避ける）。
- ⓘ アイコンを各バッジに付与し、tooltip で定義と算出方法のリンクを表示。
- 色は青系のグラデーション 1 系統に揃える（赤・橙・緑の信号配色を撤去）。

### 5.6.2 ダッシュボード

| 旧表示 | 新表示 |
|---|---|
| 平均回避度 0.32 | 平均直接回答度 0.68 / 平均コミットメント Lv 1.4 |
| スタックバー（明確/含み/回避的） | スタックバー（Lv0〜Lv4 のコミットメント分布） |
| 発言者ランキング: 平均回避度 | 発言者ランキング: コミットメント Lv 平均 + 95%CI（n<10 除外） |
| ヒートマップ: 平均回避度 / 委員会 | ヒートマップ: 議事録価値総和 / 委員会 |

### 5.6.3 既存懸念事項の継承

旧 5.4「サンプルサイズ」、旧 5.5「コンテキスト併記」、旧 5.6「閾値の UI 露出」、旧 5.7「コミットメント基準」の 4 点は、新指標体系でも引き続き必要:

1. **しきい値**: `n < 10` 除外、`n < 30` 低彩度 + n 値併記、95%CI バー併記。
2. **コンテキスト併記**: カードに「同答弁者の AS 平均」「同法案関連の Q&A 平均」を併記。
3. **閾値のバージョニング**: 集計時に閾値・モデル ID を出力に焼き込む。
4. **委員長除外・大臣別集計**: 集計対象の絞り込みフィルタを UI に置く。

### 5.6.4 「シンプル表示 / 詳細表示」の切り替え

すべての軸を常時表示すると情報過多。デフォルトは:

- **質問**: QQ-1 明確度 + QQ-5 行動要求度（2 つ）
- **答弁**: AS-1 直接回答度 + AS-4 コミットメント Lv（2 つ）
- **ペア**: OC-1 議事録価値（1 つ）

の 5 バッジに絞り、「詳細を見る」展開で残り全軸を表示する。

## 5.7 方法論ページ（旧 5.2 の P0 を継承・拡張）

「回避度の算出方法がどこにも書かれていない」という旧 5.2 の指摘は、多軸化したことで **より重要** になる。`/about/methodology` の必須項目を更新する:

1. **指標カタログ**: QQ-1〜5 / AS-1〜4 / OC-1〜3 の各定義、5 段階の例文、判定プロンプト全文。
2. **算出パイプライン**: Whisper → 話者タグ → Q&A 抽出 → 各指標判定の流れ。各段階の精度限界。
3. **既知の限界**:
   - LLM 判定の再現性（同一答弁を別モデルで再評価したときのブレ）
   - 過去会議録 RAG が本サイトのインデックス範囲に限定される（QQ-3、AS-3 の限界）
   - 1 質問 1 答弁前提の崩壊ケース（リレー答弁、ヤジ込みの議論）
4. **モデル・プロンプトのバージョニング**:
   - `metadata.json` に `score_schema_version: "2.0"` を入れ、過去データとの混在を防ぐ
   - 旧スコアは `evasion_score_v1` として併存させ、移行期間中は両方表示
5. **訂正・問い合わせ窓口**: 名誉毀損リスク対応として、対象議員・省庁からの訂正依頼を受ける明示的な窓口を置く。

## 5.8 法的・倫理的観点（旧 5.2 ｜ P0 継続）

多軸化しても本質は変わらない。**LLM 自動評価値を「事実」として表示することのリスク**は残る。むしろ指標が増えた分、誤判定の射程も広がる。

- **すべての指標バッジに「LLM 自動評価」ラベルを常時表示**（ダッシュボード上部の常時注記、各バッジの ⓘ tooltip、カード末尾のフッター）
- **断定語を避ける**: 「○○大臣のコミットメント Lv 平均が低い」ではなく「本サイト収録範囲では Lv 平均が低い傾向」と表現
- **メディア引用ガイドライン** を `/about/methodology` 内に置く（数値の引用は必ず指標バージョン・モデル ID・対象期間を併記してほしい旨）
- **個別議員への低評価の集計表示は控える**: ダッシュボードの発言者ランキングは「上位」のみ表示し、ワーストランキングは出さない（旧 5.3 のラベル過激さ問題の延長）

## 5.9 段階的移行計画（実装は別タスク）

この指標体系は一度に全部入れない。以下の順序を推奨:

| Phase | 内容 | 既存資産との関係 |
|---|---|---|
| **P0** | 用語変更のみ: 「回避度」→「直接回答度」（反転表示）。ラベル文言・色の中立化。methodology ページの最低限版 | 既存 `evasion_score` をそのまま使用、表示だけ反転 |
| **P1** | AS-4 コミットメント強度（Lv0–4）を追加。`has_commitment` を Lv に拡張 | プロンプト改修 + データ再生成 |
| **P2** | QQ-1（論点明確度）と QQ-5（行動要求度）の質問側評価を追加 | プロンプト追加。質問 intent との整合チェック |
| **P3** | AS-2（具体情報量）を機械集計ベースで追加 | LLM 不要、決定論的に算出可能 |
| **P4** | OC-1（議事録価値）合成スコアの導入。ダッシュボードの主指標を切り替え | P1〜P3 完了後 |
| **P5** | QQ-3 / AS-3（新規性・新答弁度）の RAG ベース判定 | 過去会議録インデックスの整備が前提 |
| **P6** | OC-2（追及深度）の follow-up チェーン分析、コミットメント追跡 DB | Phase 5（ダッシュボード）と統合 |

各 Phase で **A/B 比較** のため `score_schema_version` を切り、過去データの再評価コスト（DeepInfra 課金）を見積もる。6,308 ペアの再評価は概算 ¥数千円オーダー（DeepSeek V3.2 の入出力価格 × 既存 prompt サイズ）。

## 5.11 オープン論点（要 TF 議論）

1. **「総合スコア」を出すか、出さないか。** ユーザビリティ的には 1 個の数字で並べたいが、それこそが「回避度問題」の再来を招く。**出さない** を推奨するが、ランキング機能とのトレードオフがある。
2. **党固有指標の扱い。** 「マニフェスト連動度」のような特定政党の政策観に紐づく指標を、運用者向けの付帯指標として出すか、本サイトとは完全に分離するか。本サイトは党派色を出さない方針なので、**運用者向けの内部ダッシュボードに切り出す** を推奨。
3. **「いまいちな質問」を可視化するか。** 質問品質レベルの低位（前提誤り／根拠不明）を露出させると名誉毀損リスクが上がる。**レベル表示は議員別ではなく Q&A 単体に閉じる** を推奨。
4. **答弁者の役職重みづけ。** 大臣・副大臣・政府参考人で OC-1 議事録価値の重みを変えるか。変える場合の正当化（大臣答弁のほうが確かに参照されやすい）と、変えない場合の中立性（政府参考人の事実答弁こそ価値、というケースもある）。
5. **既存の「回避度」スコアの扱い。** 後方互換のため `evasion_score_v1` として残すか、完全置換するか。研究目的の引用が始まっている場合は前者。
