# 05. 「回避度」がわからない問題

[← 戻る](README.md)

ご指摘の「回避度の情報がよくわからない」は本サイトの**最も法的・社会的リスクが高いポイント**でもある。本章では、表示・方法論・統計的な妥当性の 3 観点で整理する。

---

## 5.1 現状の表示

### Q&A カード（セッション詳細・/browse 共通）
```
回避度 中（55%）
```
- 数値: `0–1` のスコアを `%` で表示
- ラベル: `< 0.3` → 低（緑）/ `< 0.7` → 中（橙）/ `>= 0.7` → 高（赤）
- 約束あり時: 緑のバー＋「約束: ○○」

### ダッシュボード
- 「平均回避度 0.32」のような数字（概要画面）
- スタックバー: clearCount（緑）/ hedgingCount（黄）/ evasiveCount（赤） の 3 セグメント
- 個別の「明確 / 検討する系 / 回避的」のカテゴリ閾値は表記なし

---

## 5.2【P0】方法論がどこにも書かれていない

### 何が問題か
- 「回避度 = 0–1」が**何を測っているのか**がサイト内に書かれていない
- LLM（DeepSeek V3.2）がどのプロンプトで何を判定しているか、ユーザーに開示されていない
- 同じ答弁を別モデルに評価させたら同じ値になる保証がない（再現性の議論）
- メディアに「○○大臣の回避度 90%」と切り取られたら、訂正できない

### 法的・社会的リスク
- 政治家の発言評価は名誉毀損訴訟に発展する可能性がある領域
- LLM 由来であることを明示しないと、**意見表明と事実陳述の境界が曖昧**になる
- 国会質疑は公開記録だが、「評価」を加えた瞬間に編集著作物になり、責任主体が運営側に移る

### 改善案: methodology ページの新設
**`/about/methodology` を必須**として作る。最低限載せるべき情報:

1. **指標の定義**:
   - 回避度 = 「質問に対する直接回答度合いを LLM が 5 段階で評価し、0–1 に正規化」
   - スケールの意味: 0 = 直接的に回答 / 0.5 = 部分回答もしくは含み / 1 = 質問内容を実質的に回答していない
2. **算出パイプライン**:
   - Whisper large-v3-turbo で文字起こし（精度限界の説明）
   - DeepSeek V3.2 で要約・評価（プロンプト全文を公開）
   - 評価軸の例文を 3 つほど（「明確に答えた例」「論点ずらしの例」「途中で別話題に移った例」）
3. **既知の限界**:
   - 1 質問 1 答弁を前提とするため、同一答弁内で複数論点を含む場合は評価が分散する
   - 質問者の意図を LLM が誤解する可能性
   - 同じ答弁でもモデル変更で値がブレる（再評価で揃える方針）
4. **更新履歴**:
   - LLM モデル ID（`deepseek-ai/DeepSeek-V3.2`）と運用開始日
   - プロンプト変更履歴

UI 側:
- 各 Q&A の回避度バッジに **❓ アイコン**を付け、tooltip で `LLM 自動評価。算出方法 →` リンクを置く
- ダッシュボード上部に「**この指標は LLM 評価値です**」の常時注記を表示

## 5.3【P0】「ラベル文言」と「色」のメッセージが過激

### 現状
- 「回避度 高」「回避的」という強い断定語
- 0.7 以上が赤＝危険信号として記号化される
- ダッシュボードのスタックバーで「明確 / 検討する系 / 回避的」の 3 ラベル

### 改善案
- 「回避度」→「**直接回答度**」(逆方向に揃え、高=明確)、もしくは「**論点充足度**」のような中立語
- 「回避的」→「**論点に直接触れていない**」「**検討中・含みのある回答**」
- 色は赤・橙・緑よりも、**青系のグラデーション**にして「色で判断させない」設計
- 評価ラベルを 5 段階に増やし、極端値（0.0 / 1.0）を出にくくする
- 「LLM 評価」を必ず併記

---

## 5.4【P0】サンプルサイズの提示が不十分

### 現状
- ダッシュボード発言者分析: 968/1160 名が `totalAnswers < 5` だが、グラフはまっすぐ全部表示
- `武村展英 totalAnswers=1, evasiveCount=1, avgEvasionScore=1.0` のような行が「100% 回避」になる

### 改善案
1. **しきい値を 2 段階に**:
   - `n < 10`: グラフから除外（「サンプル不足 ○件を非表示」と注釈）
   - `n < 30`: グラフに含めるが、棒の上に `※ n=15` を併記し、棒色を低彩度に
2. **平均回避度の代わりに信頼区間バー**:
   - 棒の上に 95% CI（信頼区間）の小エラーバーを表示
   - サンプルサイズで CI の長さが視覚的に分かる
3. **集計対象の絞り込み**:
   - 委員長は除外（質問・答弁役ではない）
   - 政府参考人と大臣を分けて集計
   - チェックボックスで「大臣のみ」「副大臣以上」「議員質問のみ」を切り替え

## 5.5【P1】Q&A 単体での「コンテキスト」が薄い

1 個の Q&A カードで「回避度 高」と表示しても、**比較対象**が無いと意味を成さない。

### 改善案
- カードに「同じ答弁者の平均回避度」を併記（例: 「この答弁: 0.85 / 平均: 0.32」）
- カードに「同じ法案関連の Q&A 平均」を併記
- 「この答弁の根拠」リンクで、LLM がどこを切り取ったかを `full_text` 上でハイライト

---

## 5.6【P1】明確／含み／回避の閾値定義が UI から消えている

`FilteredQAList.jsx` のロジック:
- `< 0.3` → 低（緑）／`< 0.7` → 中（橙）／`>= 0.7` → 高（赤）

`generate-api.ts` の `evasion.json` 集計:
- `clearCount`: `< 0.3`
- `hedgingCount`: `0.3 ≤ x < 0.7`
- `evasiveCount`: `>= 0.7`

この閾値はコード固定で UI に出ていない。**論文・記事に引用された場合に、説明責任を果たせない**。

### 改善案
- methodology ページに閾値の根拠（なぜ 0.3 / 0.7 か）を明示
- `evasion.json` 集計時に閾値を出力に焼き込む（バージョニング）
- 将来的にユーザーが閾値を変えてシミュレーションできる UI も検討

---

## 5.7【P2】「約束あり」フラグの基準

`has_commitment` は LLM が判定。緑のコミットメントバーが目を引くので、Q&A カードのデザイン上、回避度よりも「約束」が前面に出る場合がある。

### 改善案
- methodology に「約束の判定基準」を載せる（語尾「努める」「検討する」「実施する」のうちどこから約束扱いか）
- 「努力義務的な約束」と「具体的な行動約束」を 2 段階に分ける
- ダッシュボードの「約束事項数 502」もこの分類で内訳
