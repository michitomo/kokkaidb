# 09b. 関連法案タグの精度（誤タグの根本原因）

[09-law-tagging.md](09-law-tagging.md) は **recall**（タグが付かない問題）を扱った。
本章はそれと対をなす **precision**（タグが間違っている問題）を扱う。

サイト閲覧時に「明らかに誤った法案タグが付いている」と感じる体感的な印象は、実データの集計でも
裏付けられる。本章では具体例で誤タグのパターンを示し、4 つの根本原因を分解する。

## 9b.1 量的分析

タグ付き 40 セッション（140 中）の精度を、**委員会の所管省庁** との一致でチェックした
（`tools/check_law_tags.py` 相当の集計）：

| 指標 | 値 |
|------|-----|
| タグ付与セッション数 | 40 |
| 主タグ（最多 qa_id を持つ法案）が委員会所管 | 35 / 40 (**87.5%**) |
| 主タグが他省庁所管（誤り疑い） | 5 / 40 (**12.5%**) |
| 副タグ総数 | 42 |
| 副タグが委員会所管 | 28 / 42 (**66.7%**) |
| 副タグが他省庁所管（誤り疑い） | 14 / 42 (**33.3%**) |
| `qa_ids: []` で空タグ付け | 7 件（5 セッションで確認）|

要点：

- **副タグの約 1/3 が委員会所管外**。これがサイト閲覧時の「複数法案が並んでいるが、本筋と
  関係ない法案が混じっている」印象の正体。
- **主タグ自体の誤りも 12.5%**。例えば 3/11 外務委員会 に「健康保険法」が主タグとして
  12 ペアぶん紐付いている。
- **`qa_ids: []` の幽霊タグ** が存在する。Q&A が 1 つも生成されなかったセッションでも
  LLM が法案タグだけ生成しており、**実体のない関連付け**になっている。

加えて [09-law-tagging.md](09-law-tagging.md) の通り 67% のセッションでタグが 0 件なので、
**precision を上げると同時に recall も上げる必要がある** 二重課題。

## 9b.2 致命例 5 選

### 例 1: 外務委員会に「健康保険法」が主タグ（誤り）

`data/shugiin/2026/03/11/56117_外務委員会/summary.json`：

```json
{
  "session_summary": "本セッションでは、主に「在外公館職員等勤務手当法」の改正案を中心に、
                       外交官の処遇改善と人材確保、および緊迫する中東情勢への対応について審議...",
  "key_topics": ["在外公館職員の処遇改善", "イラン情勢と邦人保護", ...],
  "related_laws": [
    { "law_id": "law_025", "qa_ids": ["qa_004", "qa_005", "qa_012", ...12件] }
  ]
}
```

- **session_summary** で「在外公館職員等勤務手当法」と明記されている
- ↑ に正しく対応する `law_010`（在外公館の名称及び位置並びに在外公館に勤務する外務公務員の給与
  に関する法律の一部を改正する法律案、外務省）が **タグ付与されていない**
- 代わりに `law_025`（健康保険法等の一部を改正する法律案、厚生労働省）が **12 ペアに紐付け**

タグ付けされた qa_004 を見ると：
```json
{
  "topic": "在外職員の処遇改善と外交力の強化",
  "answer": {
    "summary": "- 共働きや子育て、介護など多様な働き方への支援が、質・量ともに職員を確保し国益を
                  増進させるために重要..."
  }
}
```

「介護」「子育て」というキーワードで **健康保険法（医療制度）** に誤連想したと推察される。

### 例 2: 災害対策特別委員会に「公債特例」「農業近代化資金」（共に誤り）

`data/shugiin/2026/04/16/56179_災害対策特別委員会/summary.json`：

```json
{
  "session_summary": "新設される「防災庁」の役割と権限...",
  "related_laws": [
    { "law_id": "law_001", "qa_ids": [...10件] },
    { "law_id": "law_029", "qa_ids": [...] }
  ]
}
```

- session は **防災庁設置法**（law_013, law_014）を中心とした審議
- にもかかわらず、**law_013 / law_014 がタグ付与されず**
- 代わりに **law_001（公債発行特例、財務省）** と **law_029（農業近代化資金融通法、農水省）** が付く

「災害」というキーワードから「災害復旧財源」→「公債」、「災害支援」→「農業」と
LLM が連想したと推察される。

### 例 3: 環境委員会の所信表明に 5 法案すべて空タグ（幽霊タグ）

`data/shugiin/2026/04/03/56141_環境委員会/summary.json`：

```json
{
  "session_summary": "宮路委員長による挨拶と理事の選任...続いて石原環境大臣が所信表明...",
  "related_laws": [
    { "law_id": "law_017", "qa_ids": [] },
    { "law_id": "law_049", "qa_ids": [] },
    { "law_id": "law_052", "qa_ids": [] },
    { "law_id": "law_059", "qa_ids": [] },
    { "law_id": "law_060", "qa_ids": [] }
  ]
}
```

- このセッションは **大臣所信表明** で `qa_pairs.pairs == []`（Q&A 0 件）
- にもかかわらず、**5 つの環境関連法案がタグ付け**されている
- すべて `qa_ids: []`（実体ペアへの参照なし）

LLM は **session_summary 単独** から「環境委員会だから環境関連法案を全部付けておこう」と
ハルシネーションしている。質的に意味のないタグ。

### 例 4: 経済産業委員会に「所得税法」が紐付き（曖昧ケース）

`data/shugiin/2026/04/22/56195_経済産業委員会/summary.json`：

```json
{
  "session_summary": "産業競争力強化法の改正に伴う国内設備投資の促進策...",
  "related_laws": [
    { "law_id": "law_015", "qa_ids": [...13件] },
    { "law_id": "law_003", "qa_ids": [...10件] },  ← 所得税法等
    { "law_id": "law_036", "qa_ids": [...1件] }
  ]
}
```

- 主審議は産業競争力強化法（law_015）✓ 正解
- ただし、**投資促進税制 (qa_009) は所得税法等の改正（law_003）の中に規定されている** ので
  技術的には law_003 の関連 qa とも言える
- 一方、経産委は形式上 law_003 を所管しない（財務金融委員会の所管）

これは **「所管委員会の精度」と「内容の精度」** が衝突するケース。LLM の判断は
「内容ベースで関連あり」だが、サイトのフィルタ（委員会別に法案を絞る）からすると
ノイズになる。設計判断が必要。

### 例 5: 環境委員会で「電気事業法」（誤り）

`data/shugiin/2026/04/28/56218_環境委員会/summary.json`：

```json
{
  "session_summary": "太陽光パネルの大量廃棄時代を見据えた『太陽電池廃棄物の再資源化等の推進
                       に関する法律案』を中心に...",
  "related_laws": [
    { "law_id": "law_049", "qa_ids": [...10件] },  ← 太陽電池廃棄物 ✓
    { "law_id": "law_036", "qa_ids": [...3件] }    ← 電気事業法 ✗
  ]
}
```

主タグ law_049 ✓。副タグ law_036（電気事業法、経産省）はおそらく**「太陽光発電 → 電気事業」**の
連想で誤って付与されている。太陽電池の廃棄物処理は電気事業法ではなく廃棄物処理法（law_059）の領域。

## 9b.3 根本原因の分解

### 原因 1: プロンプトに「委員会名」が渡されていない（最大要因）

`structurer.py:687-692` の user_prompt：

```python
user_prompt = (
    f"以下の国会質疑のQ&Aペア一覧を分析してください。\n\n"
    f"## Q&Aペア一覧\n{qa_text}"
)
if laws_text:
    user_prompt += f"\n\n## 法案一覧\n{laws_text}"
```

**`metadata.json` の committee（例: 「外務委員会」）が一切プロンプトに含まれていない**。
LLM は「これが 厚生労働委員会 なのか 外務委員会 なのか」を知らずに、Q&A 要約と 75 法案リストの
キーワードマッチで法案を選んでいる。これが 56117_外務委員会 → 健康保険法 という
**所管省庁を完全に無視した誤タグ**を生む直接原因。

### 原因 2: プロンプトが "幅広く判断" を促し過ぎている

`structurer.py:121-122` のシステムプロンプト：

```
- 法案名がtopicに含まれる場合だけでなく、質疑の内容・文脈から関連する法案を幅広く判断する
- 確信度が低いものは含めない（明らかに関連するもののみ）
```

「**幅広く判断する**」と「**明らかに関連するもののみ**」が **論理的に矛盾**している。
LLM の挙動を経験的にチューニングすると：

- 強いモデル（GPT-4o, Claude）は両者をバランスし、質の高い recall を得る
- 中位モデル（Gemma-31B）は 1 文目（幅広く）に引きずられ、副タグを過剰に拾う
- かつ 2 文目（確信度高いもの）にも引きずられ、recall が 0 件になるセッションが多発

つまり Gemma に対しては **「相反する 2 つの命令」を出している**ので、出力の挙動が
セッションごとに大きくブレる。

### 原因 3: 75 法案を一括で並べ、優先度がない

`laws_compact.txt` は 75 行 × 平均 480 字 ≒ 36KB のフラットなリスト。
LLM プロンプトに丸ごと注入されるが：

- 委員会所管・提出省庁による重み付けがない
- 提出日・成立状況による優先度がない
- 「このセッションで議論されている可能性が高い法案」のヒントが提示されていない

結果として LLM は 75 件すべての法案タイトルとキーワード照合し、表層的な単語一致を拾う。

### 原因 4: LLM 入力が "Q&A サマリー" だけで full_text が無い

`structurer.py:683-685`：

```python
qa_text = "\n".join(
    f"[{p.id}] トピック: {p.topic}\n  質問者: {p.question.speaker}（{p.question.party}）\n"
    f"  質問要旨: {p.question.summary}\n  回答要旨: {p.answer.summary}"
    for p in qa_pairs.pairs
)
```

**`question.full_text` も `answer.full_text` も含まれていない**。
- summary は「箇条書きの要点」レベルに圧縮されているので、法案名の直接言及が消えていることがある
- 例えば質疑の中で「健康保険法第 75 条」と明示的に言及されていても、要約段階でそのフレーズが
  消えている可能性がある
- 結果として LLM は「文脈の雰囲気」から法案を当てる必要があり、誤タグの確率が上がる

## 9b.4 推奨される修正方針

### A. プロンプトに委員会名を明示的に注入（即効性あり、コスト 0）

```python
user_prompt = (
    f"以下の国会質疑を分析してください。\n\n"
    f"## セッション情報\n"
    f"院: {chamber_ja}（衆議院／参議院）\n"
    f"委員会: {committee}（例: 厚生労働委員会、外務委員会）\n"
    f"日付: {date}\n\n"
    f"## Q&Aペア一覧\n{qa_text}\n\n"
    f"## 法案一覧（このセッションで議論される可能性が高い順）\n{laws_text}"
)
```

これだけで「外務委員会で 健康保険法を主タグにする」ような誤りは大幅に減る見込み。

### B. 委員会 → 所管省庁マッピングで法案リストを 2 段階フィルタ

[09-law-tagging.md §9.2 改善案 (2)](09-law-tagging.md#改善案) の通り、
予選フィルタを行えば 75 法案 → 14 法案 程度に絞れる。

```python
def get_relevant_laws(committee, all_laws, expand_to_all_if_empty=True):
    primary = COMMITTEE_TO_SUBMITTERS.get(committee, set())
    matches = [b for b in all_laws if b.submitter in primary]
    return matches if matches else all_laws
```

LLM プロンプトには「**このセッションで議論される可能性が高い法案 (14 件)**」として注入し、
**末尾に「上記以外の参考として全 75 件」も付ける** ハイブリッド方式。これなら recall も
保てる。

### C. プロンプトの矛盾解消

`structurer.py:121-122` を：

```
## 関連法案タグ付けルール
1. **委員会の所管法案を優先**：このセッションは {committee} なので、{primary_ministries} 所管の
   法案が中心となる前提で判断してください。
2. **直接審議の法案を主タグに**：session_summary に明記された法案、または複数 qa_id が直接
   議論している法案を「主タグ」とし、qa_ids にすべての関連 ID を含めてください。
3. **副タグは慎重に**：他の法案を関連付ける場合は、qa_id が法案名を明示的に言及している場合に
   限ってください。会話のキーワードからの連想だけでは付与しないでください。
4. **qa_id への紐付けが無いタグは出力しない**：related_laws[].qa_ids が空配列になる法案は
   含めないでください。
```

特に 4. が重要：[9b.2 例 3](#例-3-環境委員会の所信表明に-5-法案すべて空タグ幽霊タグ) の幽霊タグを
確実に弾ける。

### D. Q&A ペア単位でのタグ付け（[09-law-tagging.md §9.2 改善案 (1)](09-law-tagging.md#改善案)）

セッション単位ではなく Q&A ペア単位で tagging する。各ペアの full_text + 周辺文脈を
LLM に渡し、「このペアは law_001..law_075 のうちどれと関連するか（複数可、なしも可）」を
聞く。委員会フィルタ済みの 14 法案リストを使えば判定が安定する。

### E. ハルシネーション防止のバリデーション

site/scripts/generate-api.ts または整合性チェックステップで：

```python
def validate_law_tags(summary, qa_pairs, laws):
    issues = []
    for rl in summary.related_laws:
        # qa_ids が空なら除去
        if not rl.qa_ids:
            issues.append(f"law tag {rl.law_id} has no qa_ids; removing")
            continue
        # qa_ids が実在しない qa_id を参照していたら除去
        valid_qa = {p.id for p in qa_pairs.pairs}
        rl.qa_ids = [q for q in rl.qa_ids if q in valid_qa]
        if not rl.qa_ids:
            issues.append(f"law tag {rl.law_id} all qa_ids invalid; removing")
            continue
    return issues
```

これは LLM の出力を信頼せずポストプロセスで担保する保険。

## 9b.5 改善後の期待値

A〜E を実装した場合の見込み：

| 指標 | 現状 | 期待値 |
|------|------|--------|
| 主タグ正解率 | 87.5% | 98%+ |
| 副タグ正解率 | 66.7% | 85%+ |
| `qa_ids: []` 幽霊タグ | 7 件 | 0 件 |
| タグ 0 件のセッション | 94 / 140 (67%) | 30 / 140 程度 (20%) |

**A（委員会名注入）は 1 行追加で済むコストゼロの修正**。これだけで誤タグの大半は減るはずなので、
最優先で実装して効果を測定するのが望ましい。
